# 部署与运维

## 部署边界

GitHub Pages 仅发布 web/ 中的静态前端，不运行 Python、PostgreSQL 或后台任务。需要自行准备后端 Linux 主机、域名和实际模型服务。没有部署并完成真实模型验收前，不应对外宣称“已经生产上线”。

当前提供单主机生产部署拓扑，不具备跨主机自动故障切换；容量必须依据实际主机与模型实测，不承诺未经验证的并发数。

## 初次部署

1. 在后端主机安装 Docker Engine 与 Compose；域名指向主机。只向公网开放 80/443，数据库不得开放公网端口。
2. 复制 .env.example 为 .env，修改数据库密码和 DATABASE_URL，填入模型的 OpenAI-compatible /v1 地址、MODEL_NAME、MODEL_API_KEY。密码中的特殊字符需 URL 编码。不要把 .env 上传到 GitHub。不要在聊天或工单中贴密钥。
3. 执行 `docker compose up -d --build`。迁移容器成功后，API 和 Worker 才启动。首次语义模型下载需要网络；受限环境需提前准备模型缓存卷。
4. 执行 `docker compose exec api python -m scripts.bootstrap`，交互输入租户、管理员邮箱和至少14位密码。没有默认管理员密码。
5. 执行 `docker compose exec api python -m scripts.preflight`。此命令会调用真实模型完成一个很小的 JSON 响应检查，会消耗模型额度；不打印密钥或模型内容。
6. 执行 `docker compose --profile public up -d gateway`。确认域名已解析、80/443可达；Caddy 自动申请和续期 TLS。
7. 验证 `https://你的域名/api/health` 与 `/api/ready`。health 仅代表 API 活着，ready 同时检查数据库与 Worker 最近心跳，不代表模型效果达标。
8. 同源访问后端网页，或由部署者在 web/config.json 的 api_base_url 配置 HTTPS 后端地址后发布 GitHub Pages。访问者无需填写服务地址。CORS_ORIGINS 必须包含准确的前端 Origin，不含路径；不用通配符。
9. 由管理员创建普通成员、分析师或审核人，导入真实业务资料，并完成权限与工作流验收。

## 上线检查

- 模型服务数据处理协议与企业数据外发政策已确认；私有资料不能未经许可发送第三方模型。
- 管理员、普通用户、另一个租户进行正向与越权验证。禁用用户的既有会话须立即失效。
- 使用实际模型验证正常、无证据、恶意文档指令和模型超时场景。
- Worker 中断后任务可重新认领；旧 Worker 不能覆盖新 Worker 结果。
- 确认数据库持久卷、备份保留与恢复演练；不可只确认“备份命令返回成功”。
- 配置日志采集、错误率/延迟/队列积压告警；当前项目提供日志与状态接口，不自称接入了企业告警平台。
- 做实际负载测试，记录硬件、数据规模、模型、并发、P50/P95、失败率和测试时段。
- 定期扫描镜像与依赖；上线时固定经验证的镜像 digest，升级前复测。当前 Dockerfile 使用兼容版本约束，不等价于供应链审计完成。
- 数据库运行账号应按组织策略限制权限；不能把测试数据库凭据带入生产。
- 本地桌面环境未运行 Docker daemon；容器验证交由 CI，不把本地语法检查等同于部署成功。

## 备份和恢复

备份对象：PostgreSQL 中的账号、会话、审计、任务、文档/订单/报告；语义模型缓存可重建，不是业务备份。使用 PostgreSQL `pg_dump -Fc`，将备份文件写入受控加密存储，制定异机副本与保留周期。备份文件包含敏感业务数据，禁止提交 GitHub。

恢复演练必须在**新数据库/新持久卷**执行，不能覆盖当前生产实例。使用 `pg_restore` 导入后核验表计数、最近任务、抽样报告与文档检索，最后才切换流量。默认迁移禁止破坏性 downgrade；应用回滚优先使用与当前 schema 兼容的旧镜像，必要时从验证过的备份恢复到新环境。

## 故障定位

1. 保存响应 X-Request-ID 或任务 ID；用 ID 查 API/Worker 日志，不在日志记录访问令牌、密码或完整模型请求。
2. ready=503：先查数据库健康，再查 Worker 心跳。API 活着不代表后台任务可执行。
3. 任务 queued：检查 Worker 是否在线、迁移是否成功、是否有长期运行任务占用 Worker。
4. 任务 failed：查看服务端异常；修复配置或输入后人工重试，避免无限烧模型额度。
5. 浏览器连接失败：检查 HTTPS、域名、CORS Origin、服务地址是否多写了 /api、证书和反向代理。
6. 模型 JSON 不合法/超时：请求或任务明确失败，不伪造回答；先运行 preflight，再复现业务请求。
