## 检索：先增加区分度，不先修改答案

新增 28 个文档版本，其中两组共享 document_key，按真实索引流程更新同一个 Document；最终26个活动文档，含1个其他租户的干扰文档。24道题包含21道有答案题、2道权限拒答题和1道无答案题。

必需文字覆盖只在有 `required_evidence` 标注的5道题上计算，是精确文本字段检查，不是语义支持率。权限用例和禁用证据检查在本次全部通过，不代表任意攻击下永远不会泄漏。

失败 h16：“这个的过期时间是多久？”缺少订单导出上下文时，BM25/向量/混合均漏召回；补上明确的历史问题后召回了导出说明。失败 h05：两个近似错误码需要两份文档，当前融合仍只命中一个；该失败保留在结果中。

本次没有为了提高分数删题或改相关文档标注。扩展策略是规则改写与父上下文的联合实验，不能把联合效果当作单模块因果收益。相对纯向量的16.67个百分点差异仅限这个开发集；需要独立保留集与更大样本验证。

## 解析：真实 OCR 的复杂资料测试

8道困难题另做真实DeepSeek调用：无接口错误，5条非拒答输出通过引用契约；预期行为匹配7/8。h05因必要证据未召回而拒答，属于检索导致的过度拒答，不是可以删除的“坏分数”。详见 `hard-live-evaluation.json`。未进行独立人工事实正确率评分。

生成并识别3份图像PDF：双栏排障说明、合并表头、含空白附页的多页文件。4页全部保留，11个预设关键字符串都出现；所有文档进入复核，空白页未确认时拒绝提交。

双栏正文在修复前生成表格候选，修复后改为“布局不确定”。规则使用完整句子结尾作为保守线索，不是通用版面分类器。合并表头目前保留为文字加普通表格，不重建跨列单元格关系。

字段出现率不能替代字符正确率、阅读顺序正确率或表格单元格准确率。尤其“30”也可能是“3000”的子串，因此该样例只提供基础回归信号；行列关系仍须看原图。

证据：`complex-ingestion-baseline.json`、`complex-ingestion-evaluation.json`，原始测试PDF位于 `data/fixtures/complex/`。自动脚本里的复核模拟不计作独立人评。

## 复现

```bash
python -m scripts.evaluate_production --dataset data/hard-evaluation.json --corpus data/hard-corpus.json --output docs/hard-evaluation.json
python -m scripts.evaluate_ingestion --font /path/to/chinese-font.ttf
```

OCR测试依赖 `.[ocr]` 和中文字体。报告带数据集与语料摘要，人工标签仍绑定具体结果文件；调参后必须重新运行，不把新旧结果混在一起。
